## Design Specificity Verdict

Authored for this product, not marginally. strengthOf() demotes cosine to words because a recruiter cannot
calibrate 0.413 against 0.307. The export is labelled "Export shortlist (.csv)" with a comment explaining why.
The weak flag renders ABOVE the list, before names can be misread as a recommendation. Serif names on #fbfaf8
paper: it reads like a document, not a dashboard — correct for a surface whose content is documents about people.

Where character thins: the candidate card carries no dates, title, location or availability — the four things a
recruiter triages on. "Closest passage" shows a section NAME, so the product's central claim (a payments match on
a CV that never says "payments") is asserted in the intro and never demonstrated in the results.

Deterministic scan (full parser, after installing htmlparser2/css-select/css-tree/domutils): 3 findings —
flat-type-hierarchy (7 real sizes, 1.9:1), pulsing-dot, overused-font (false positive: matches "Roboto" as source
text, 5th in the stack). The earlier degraded regex run found 1 and inflated the size list to 16 spurious values.

Contrast: 22 pairs per scheme, ZERO AA failures. Lowest light 5.24, lowest dark 6.53. Non-text contrast is weak:
card vs page 1.04, hairlines 1.19-1.28. No browser overlay injected; measured DOM evidence used instead.

## What's Working

1. The weak-match state is a genuine competitive advantage, built as one. The flag comes from the API so the UI
   never infers "nobody fits" from prose, and the banner renders above the list.
2. The similarity score is demoted deliberately and completely, consistently across card, System panel and CSV.
3. The CV viewer's matched-section marker plus the provenance note pre-empts the confusion that sinks CV tools.

## Priority Issues

### P0 - The ranking asserts an absence the CV contradicts
Verified reproducibly. The answer states ventilator experience "is not stated in her CV". Grace Okonkwo's CV says
"Twelve-bed adult ICU. Ventilator management, continuous renal replacement therapy". She was the only candidate
above threshold.

ROOT CAUSE, pinned in source: _context_for() in search.py sends ONE chunk - the single best-scoring section -
plus a 400-char header. Grace's best chunk was "Professional Summary", which does not mention ventilators. The ICU
role chunk that does was never sent. The model obeyed its instructions; the architecture conflates "absent from
this excerpt" with "absent from the CV".

This is the inverse of the failure the grounding prompt was built to prevent. It guards against fabricated
presence; nothing guards against fabricated absence - and the absence is the one that gets believed.

Fix: send all chunks for the k retrieved candidates (k is 5; cost is trivial), and constrain the prompt so an
absence may only be asserted about the excerpts provided, in those words. Command: /impeccable harden

### P0 - Demo data is distinguishable only by a collection NAME
The guard is /demo|test|sample/i against h.collection. On the VPS the demo instance is cvs_demo and fires
correctly. But the local dev corpus in .chroma-dev is named "cvs", so anyone running locally sees five synthetic
people with UAE phone numbers, visa status and named employers and NO indication they are generated. Product
principle 4 is "demo data must never be mistakable for real people."
Fix: /health returns an explicit synthetic boolean recorded at index time; banner shows whenever absent or true.
Prefix synthetic names in the API response so the marker survives CSV export. Command: /impeccable harden

### P1 - Strong and Weak matches are visually identical and equally shortlistable
They differ by one .8rem word's colour and a 3px bar. On the veterinary brief - where the banner said nobody meets
the bar - all five remained one click from a shortlist and an export to real people.
Fix: make weakness structural, not chromatic. Collapse below-threshold cards behind a disclosure. Move the count
line below the banner. Command: /impeccable layout

### P1 - "Closest passage" shows a section label, not the passage
Three of five cards read "Profile" or "Career Summary" - zero information. One showed a chunk header truncated
mid-word. With k up to 20 the card list is the only triage tool and carries no content.
Fix: return the matched chunk text from /search, render ~2 lines on the card. Command: /impeccable clarify

### P1 - Nothing async is announced; the search box has no focus ring
Zero aria-live, zero role=status/alert, zero landmarks, no main, no skip link. Focus returns to the composer, the
LAST element in the DOM - 34 tab stops after the results. Headings break h1 to h3 once results render.
textarea:focus{outline:none} (line 295, specificity 0,1,1) beats :focus-visible (line 314, 0,1,0). All 23 controls
are under 44px in an axis; shortlist checkbox 16.8x16.8, Explain checkbox 13x13 - both fail WCAG 2.2 SC 2.5.8.
Command: /impeccable audit

### P2 - The shortlist is anonymous, volatile, one misclick from gone
A count with no names, no per-person remove, in-memory only, no confirm on Clear. The tray is in normal flow, so
it steals ~48px of the results viewport at the moment of commitment. Command: /impeccable harden

### P2 - Raw markdown artifacts leak into the ranking block
md() has no hr branch, no ordered-list branch, and its citation regex requires an @, so bare local-parts render
raw at full weight beside dimmed ones in the same sentence. Command: /impeccable clarify

## Minor Observations

- System panel's dl starts at the window edge while content is centred in a 46rem column: ~400px of dead space.
- The candidate's name prints twice in the CV viewer (card h3, then header section h5).
- .meter scales against a hardcoded 0.6 ceiling, so bar width and badge word can disagree at a glance.
- #k has no label association; its meaning comes from adjacent text nodes.
- #csv flips to "Preparing..." then back to idle - a successful export and a no-op look identical.
- No URL state: a brief cannot be bookmarked, shared or reloaded.
- Type: 17 declared font-size values, 11 inside a 0.15rem band; body is 15px, under the 16px floor; three

  parse ordering in md() is correct.
